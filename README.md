# Minecraft Tools

A collection of tools for everyday Minecraft play: a seed map, enchanting and villager trading guides,
banner, shield and firework generators, a build checklist, calculators and more. Everything runs in the
browser.

**Stack:** Vite · TanStack Router (file-based) · React 19 · Tailwind v4 · shadcn/ui on Base UI · oxlint + oxfmt · Bun

## Development

```bash
bun install
bun dev            # http://localhost:5173
bun run build      # type-check + production build in dist/
bun run lint       # oxlint
bun run format     # oxfmt
bun run knip       # unused files, exports and dependencies
bun run test       # vitest (bun run test:watch while working)
bun run check      # all of the above, what the pre-commit hook runs
```

`bun install` sets up a pre-commit hook (husky): it formats and lints the staged files, then runs
the type check, knip and the tests, and stops the commit if any fails. The tests in `tests/` check
the game data (every trade item has a name, every pattern its textures, languages agree...), that
tools, routes and search pages match, and the rules behind the tools (anvil costs, seeds, circles).

Routes live in `src/routes/` (`src/routeTree.gen.ts` is generated by the router plugin). The build
writes one html file per page into `dist/`; the host serves that folder and falls back to `404.html`
for unknown paths.

A new tool goes in `src/components/tools.ts` (the header menu, search, main page, page title and
the "Related tools" box read from it; `related` lists the three tools shown under it) and `PAGES` in
`src/lib/seo.ts`, with a picture in `public/tools/`.

## Game data

Most tools read data or textures taken from the game. They are committed, so the site works as is;
run a sync script when a Minecraft release changes what a tool needs, then commit the result.

```bash
bun run sync                  # all of the below at once, for the latest release
bun run sync 26.3             # ...or a specific version
bun run items:sync            # item checklist: versions and item catalog in src/data/
bun run armor:sync            # armor trim viewer: public/armor/ and src/data/armor.json
bun run armor:sync 26.3       # ...or a specific version
bun run banner:sync           # banner and shield generators: public/banner/, public/shield/, src/data/banner.json
bun run potions:sync          # potion maker: public/potion/
bun run decor:sync            # background block textures in public/decor/
bun run villagers:sync        # villager trading guide: every trade in src/data/villagers.json
bun run lang:sync             # official names in every language in src/data/lang/ (after items:sync and villagers:sync)
```

`items:sync` reads the [mcitemgallery.com](https://mcitemgallery.com) manifests and records which CDN
folder holds each item icon per version; the icons themselves are not stored here. The other scripts
download the official client jar once into `.cache/` (git-ignored) and extract the textures from it.

## Translations

The site is in English, Portuguese (Brazil) and Spanish (Spain). Game names (items, biomes,
enchantments, effects, potions, banner patterns, trims...) are never translated by hand: `lang:sync`
takes them from Minecraft's own language files, so they read exactly like in game. The site's own
text lives in `src/i18n/messages/`; a new string goes into `en.ts`, `pt-BR.ts` and `es.ts`, and the
type check fails if a language misses it. Page titles and descriptions for search engines are in
`src/i18n/pages.ts`; the prerendered html stays English.

## Seed map engine

World generation is [cubiomes](https://github.com/Cubitect/cubiomes) compiled to WebAssembly. The
binary is committed (`public/engine/engine.wasm`), so it only needs rebuilding after bumping the pinned
cubiomes commit in `scripts/build-engine.ts` or changing `native/engine.c`:

```bash
pip install ziglang     # only used as a C compiler
bun run engine:build
```

## AI disclosure

AI assistants were used while developing this project, mainly to write and refactor code, and all of
their work was reviewed by hand. The content itself does not come from AI:

- **No image is AI-generated.** Textures come from the game, item icons from mcitemgallery.com,
  interface icons from pixelarticons, and the tool pictures are the game's own item icons.
- **Game data is extracted, not written.** Items, trades, names and translations are pulled from the
  official game files by the sync scripts, and world generation is cubiomes, which mirrors the game's
  own code.
- **Rules and numbers are checked against trusted sources**, mainly the game files and minecraft.wiki,
  which is cited in the code where it is used.
